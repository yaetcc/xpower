> 本文档汇总全部历史需求（TapeX 老项目继承 + XPower 定稿 + 用户反馈），作为 v4 重写的完整 spec。

## 一、项目定位

**XPower = 三币闭环 DApp 发射台（Launchpad）**：任何人在 IGNIX 发币后，粘贴代币地址一键起盘自己的「盲盒抽卡 → 组装 PC → 质押挖矿 → 领取分红」闭环项目。玩家来玩你的币，你来发射你的闭环。

| 角色 | 行为 |
|---|---|
| 创建者 | IGNIX 发币 → 粘贴代币地址 → 配置盲盒（总量/单价/8 部件权重）→ 一键部署 |
| 玩家 | 花项目代币抽部件 → 花 XPR 组装 PC → 质押挖矿赚项目代币 → 市场交易 |

## 二、三币闭环经济（核心定稿）

| 环节 | 消耗 / 产出 | 代币 | 流向 |
|---|---|---|---|
| 盲盒抽部件 | 消耗 | **用户指定代币**（IGNIX 发币） | 90% 分红池 / 10% 创建者 |
| 部件组装 PC | 组装费 | **平台币 XPR**（10 XPR/台） | 平台收款地址 |
| 质押挖矿 | 产出 | 用户指定代币 | 按质押算力份额分配（6h 周期） |
| 市场交易 | 结算 | 用户指定代币 | P2P 零手续费 |

**平台常量（X Layer · Chain 196）**
- 平台币 XPR：`0xFa24321d8f37B588a4f76FC18795Bcd441DCeEEe`
- 平台收款地址（组装费等全部归此）：`0x594c2c32cb60a0d93f0ce1cc9f6088709b50addc`
- 公开 RPC：`https://rpc.xlayer.tech`（**内置 3+ 备用 RPC 自动切换 + 重试，杜绝 Failed to fetch**）
- 组装单价：10 XPR/台（合约常量，前端展示）

## 三、核心玩法（四步闭环）

1. **STEP1 盲盒抽部件**：花项目代币开盒 → 按权重随机 8 类硬件部件（CPU/主板/GPU/内存/SSD/电源/散热/机箱）→ 可批量
2. **STEP2 组装整机**：8 类部件各 1 合成 PC NFT → 档位 1-5 随机决定算力 → 消耗 XPR
3. **STEP3 质押挖矿**：PC 质押进矿池 → 按算力占比瓜分 6h 分红池（项目代币）
4. **STEP4 领取奖励**：随时领取累计分红

- 输入框聚焦不触发页面缩放（`font-size≥16px`）

## 七、问题根因分析与 v4 对策

| 问题 | 根因 | v4 对策 |
|---|---|---|
| `could not decode result data` 连环 | 官方模板旧实现 vs 前端新 ABI 不匹配；补丁式容错有遗漏 | 官方模板用与前端**同源**新合约重部署；ABI 从编译产物生成单一数据源 |
| 一键部署失败 / 16 笔 | 部分链路缺显式 from/gas/超时；回退脆弱 | 统一交易封装；一键为主，逐笔仅诊断 |
| RPC 限流 Failed to fetch | 公共 RPC 不稳定无重试 | 读取层内置重试 + 备用 RPC 切换 |
| 前端补丁堆叠不可维护 | 反复小修 | 从零重写，一次性成型 |

## 八、v4 技术方案

### 8.1 合约（单文件 6 合约，UUPS 可升级代理）
| 合约 | 职责 | v4 增强 |
|---|---|---|
| XPowerParts | 部件 ERC-1155（8 类） | — |
| XPowerCircuit | 组装 PC（8 部件→1-5 档→算力），收 XPR 至平台 | + `assembleWithTier(tier)` 自选品质；+ `batchAssemble`（保留） |
| XPowerMining | 质押挖矿，按算力分 6h 池 | + `batchStake/batchUnstake/batchClaim` |
| XPowerBox | 盲盒协议（90/10 分账） | + `batchOpenBox`；权重在 initialize 写入 |
| XPowerMarket | P2P 市场 | + `batchSellParts/batchSellPCs/batchCancel`（保留） |
| XPowerFactory | 一键部署聚合 | `deployProject` 1 笔签名；新官方模板与此同源 |

- 编译：solc 0.8.17 · optimizer 200 · **via-ir**（必须，initialize 参数多触发 stack too deep）
- 交付：源码 + ABI/bytecode + foundry 测试 + verify-flat 平面化源码

### 8.2 前端（单文件 HTML 从零重写）
- **单一数据源**：ABI/地址内嵌并与编译产物逐字段核对
- **统一读取层**：`chainRead(contract, method, args, fallback)` 所有读取走此函数（超时/重试/降级）
- **统一写入层**：队列执行器包裹所有签名交易
- **页面**：发射台 / 项目列表 / 项目详情（STEP1-4+市场，页内闭环）/ 我的资产（含我创建的项目）
- ethers 动态加载（不阻塞 UI）；OKX 钱包；Chain 196
- **RPC 稳健**：主 RPC + 3+ 备用自动切换，读取/写入统一重试（超时→换 RPC→重试→降级），全流程验证链上交互

### 8.3 v4 交付前验证清单（链上交互全流程）
1. forge 测试：部署/开盒/组装/质押/领取/市场/批量 全绿
2. 官方模板新部署，ABI 逐字段核对
3. 一键部署成功 → 自动跳项目页 → 5 地址回显
4. 玩家链路实测：抽卡→组装（费入 0x594c…baddc）→质押→领取→挂单/购买
5. 批量：队列执行器 排队/终止/重试
6. 移动端：无溢出、不缩放、不跳版
7. RPC 故障模拟：备用切换 + 降级显示

- 无演示模式、无演示钱包、无假数据
- 无项目选择器（盲盒列表直达项目）

- 无盲盒创建费、无平台分成抽佣（分成 90/10 已定稿，平台不再另抽）
- 不做合约外部依赖迁移（v4 全新部署，无需资产迁移）

## 十、验收标准（v4 完成定义）
1. 合约本地 forge 测试全绿（部署/开盒/组装/质押/领取/市场/批量）
